# שער A — בדיקת Windows ארוזה

מסמך תוצאות. כל הרצה נרשמת כאן עם גרסאות, חומרה, זמנים וצילומי מסך.
הקריטריון: **התוסף הארוז** פועל. בדיקה מ־localhost לבדה אינה מספיקה.

מקור השער: [../../docs/word-plugin-implementation-plan.md](../../docs/word-plugin-implementation-plan.md) §6.3.

---

## מצב: השער לא עבר. מוכן להרצה, אין חוסם.

האריזה נבדקה מ־`file://` ב־Google Chrome headless על macOS ועובדת: `onReady`
תוך 485ms, עריכה, ייצוא DOCX, אפס שגיאות. הפרטים: [spike.md](spike.md) §3.

זו אינדיקציה, לא השער. השער דורש את התוסף **הארוז**, ב־WebView2, בתוך אוצריא,
על Windows. עד שזה יורץ חסומים ה־Ribbon, אינטגרציית השמירה ב־`v2/` וכל הפצה.
PR הכתיבה ב־SDK של אוצריא אינו חסום ונבנה מוקדם בכוונה — ראו
[spike.md](spike.md) §תוצאה.

מה שנשאר הוא בדיוק מה שאי אפשר לעשות מ־macOS: הרצה ב־WebView2 על Windows, עם
אריזה אמיתית של `otzaria pack-plugin` ועם מסמכים אמיתיים.

> גרסה קודמת של המסמך הזה קבעה שהשער חסום ודורש שינוי בצד אוצריא. זה היה שגוי —
> ההנחה הייתה שקוד ה־worker חייב module. הדרישה ההיא מבוטלת.

**נקודת התורפה שיש לבדוק קודם כול:** ה־workers נטענים כ־workers **קלאסיים**,
דרך עטיפה של בנאי ה־`Worker` שמסירה `type: 'module'` מה־blob URLs שלנו
(`src/engine/workers.ts`). זה עובד ב־Chrome; WebView2 הוא Chromium, אך זו אינה
הוכחה. אם הטעינה נכשלת ב־WebView2, ה־console יראה `module-load-failed` או שגיאת
worker, וזה הדבר הראשון לבדוק.

## הצ'קליסט

### 1. אריזה — נעשה על macOS

- [x] `cd v2 && npm ci && npm run verify` — typecheck, בדיקות, build ו־check:dist.
- [x] אריזה: `exit 0`, 8 קבצים, **4.32MB**. הגופן הארוז נוסף אחרי המדידה הזאת
  ומוסיף 70KB ל־ZIP; יש לארוז מחדש ולרשום את המספר.
- [x] הגופן הארוז נטען מ־`file://` ב־Chromium (`npm run check:fonts`) — לא
  הוכחה ל־WebView2.
- [x] הוולידטור עובר, כולל `✓ העיצוב תואם לתיעוד (DESIGN_GUIDE)`.
- [ ] לחזור על האריזה על Windows (אותו CLI, כדי לשלול הפרשי נתיבים/הרשאות).

### 2. התוסף הארוז — השער עצמו

- [ ] התקנה ב־Windows: הגדרות ← ניהול תוספים ← התקנה מקובץ.
- [ ] פתיחת הלשונית „וורד לאוצריא”. שורת המצב מציגה גרסת אוצריא ופלטפורמה.
- [ ] **הלשונית עולה בפתיחה הראשונה**, בלי „אוצריא לא סיימה לאתחל את התוסף”
  ובלי רענון. זה נכשל ב־macOS לפני ה־latch של plugin.boot (ראו spike.md §6);
  אם זה חוזר, ה־console יכיל שורת אבחון `[otzaria-word] כשל אתחול` עם
  `latchRan`, `sdkBooted` ו־`lastRpcError` — אוצריא מעבירה console של תוסף
  ללוג שלה.
- [ ] מסמך ריק נפתח. **document worker ו־review-index worker נטענים** — לבדוק
  ב־DevTools ← Sources/Network שאין שגיאת worker ואין בקשת רשת יוצאת.
- [ ] „פתיחת קובץ Word” → מסמך עברי קטן. RTL, ניקוד, טעמים, גופנים.
- [ ] **הגופן הארוז נטען ב־WebView2** — ב־DevTools ← Network בקשה מוצלחת
  ל־`fonts/Assistant-Regular.ttf`.
- [ ] **הממשק מוצג ב־Assistant, בעברית ולא רק בלטינית.** הגופן הארוז
  (`src/styles/fonts.ts`) מוצהר בשמו בלבד, בלי `unicode-range` ובלי שם התאמה,
  ולכן הוא אמור לתפוס גם את העברית שבממשק. **זה נבדק ביחידה על מה שמוצהר
  ובשער `check:fonts` על רוחב טקסט, לא על העין**, ולכן צריך לראות את זה על
  Windows: כתוביות הכפתורים במשקל 500/600 צריכות להיראות באותו גופן כמו הטקסט
  הרגיל, ולא בגופן המערכת.
- [ ] עריכת מילה; „מודגש” ו„כיוון מימין לשמאל” משנים את המסמך.
- [ ] **הקלדת מילה מסמנת „לא נשמר”.** זה החיבור היחיד בשמירה שלא נבדק
  אוטומטית: `onEditorUpdate` מחובר ונבדק ביחידה, אבל שהמנוע באמת קורא לו על
  הקשה אפשר לאמת רק בהקלדה אמיתית (סינתוז הקלדה ל-ProseMirror ב-headless לא
  עבד). אם זה נכשל — „שמור” לא ידע שיש מה לשמור.
- [ ] „שמור” על מסמך חדש פותח „שמור בשם”, והקובץ נפתח ב-Word.
- [ ] „שמור” שני כותב לאותו קובץ **בלי דיאלוג**, ושורת המצב מציגה „נשמר”.
- [ ] Ctrl+S שומר; Ctrl+Shift+S פותח „שמור בשם”.
- [ ] ביטול „שמור בשם” משאיר „לא נשמר” ואינו מציג שגיאה.
- [ ] עריכה, המתנה של 2.5 שניות בלי לגעת — autosave שומר לבד (רק אחרי שיש יעד).
- [ ] פתיחת קובץ שהמשתמש בחר: השמירה הראשונה עליו כותבת לאותו קובץ בלי דיאלוג
  (הוא נפתח עם `access: 'readwrite'`).
- [ ] **מעבר מסמך עם שינויים לא שמורים** — שלושת המסלולים, כי כאן אובדת עבודה:
  „לשמור?” → כן → נשמר ואז נפתח החדש; „לשמור?” → לא → „לפתוח בלי לשמור?” → כן
  → נפתח והשינויים נמחקו; „לפתוח בלי לשמור?” → לא → כלום לא קרה.
  (במסמך נקי אין לשאול כלום — אומת ב־Chrome.)
- [ ] „לשמור?” → כן, וה־„שמור בשם” **מבוטל** → הפתיחה נעצרת והמסמך נשאר פתוח.
- [ ] לחיצה על „פתיחת קובץ” בזמן שמירה — מוצגת הודעה ולא נפתח דיאלוג.
- [ ] **סגירה ופתיחה מחדש של הלשונית** — המסמך האחרון נפתח לבד, ו„שמור” כותב
  אליו בלי דיאלוג (ה־`access` נשמר לצד ה־token).
- [ ] אותו דבר אחרי סגירת אוצריא והפעלתה מחדש (הפורט של ה־loopback מתחלף —
  זה בדיוק מה ש־`fs.resolveFileUrl` פותר).
- [ ] מסמך שנמחק מהדיסק בין ההפעלות → נפתח מסמך ריק עם הודעה, בלי לולאת שגיאה.
- [ ] מצב הכפתור „מודגש” מתעדכן כשמזיזים את הסמן בין טקסט מודגש לרגיל.
- [ ] „ייצוא ל־Word” → הקובץ נפתח ב־Microsoft Word ונראה נכון.
- [ ] מסמך של 50 עמודים: זמן פתיחה, גלילה, peak memory.
- [ ] console נקי.
