# תוכנית עבודה — קיצורי מקלדת

- תאריך: 25.8.2026
- בסיס: `main` בקומיט `f1560d0`
- ענף העבודה: `feat/keyboard-shortcuts`
- יעד סופי: PR ל‑`Y-PLONI/otzaria-word-editor`

מסמך זה הוא תוכנית העבודה של המשימה, והוא נכתב כדי שיעבדו לפיו שלב אחר שלב.
כל שלב נסגר בקומיט משלו, ואינו נפתח לפני שהשלב שלפניו ירוק ב‑`npm run verify`.
בין השלבים יש ארבע נקודות QA שבהן סוכן בודק את מה שנעשה מול המסמך הזה.

---

## 1. הממצא — מה קיים היום

התוסף מממש שישה קיצורים בלבד, כולם ב‑`src/App.vue:888-925`:

| קיצור | פעולה | מימוש |
|---|---|---|
| `Ctrl+S` / `Ctrl+Shift+S` | שמור / שמור בשם | `saveShortcut` ב‑`src/sessions/open-flow.ts:90` |
| `Ctrl+F` / `Ctrl+H` | חיפוש / החלפה | `openFindDialog` |
| `Ctrl+P` | הדפסה | `onPrint` |
| `Escape` | סגירת דיאלוג חיפוש / אודות | inline |

מלבדם יש ניווט מקלדת מקומי שאינו „קיצור” במובן הזה: חצים בין לשוניות הרצועה
(`src/ui/ribbon/Ribbon.vue:184`), `Esc`/`Tab` בדיאלוגים, וניווט בבורר הטבלה.

**שני ליקויים שהתוכנית באה לתקן:**

1. **תוויות שמשקרות.** ברצועה מוצגות 17 תוויות קיצור. הפרופ `shortcut`
   ב‑`src/ui/ribbon/common/RibbonButton.vue:72` רק משרשר טקסט ל‑tooltip — הוא
   אינו רושם שום binding. שתים‑עשרה מהן (`Ctrl+B`, `Ctrl+I`, `Ctrl+U`,
   `Ctrl+R/E/L/J`, `Ctrl+]`, `Ctrl+[`, `Ctrl+C/X/V`) אינן קיימות בקוד שלנו. הן
   יעבדו רק אם מנוע העריכה קושר אותן בעצמו, ואת מעטפת ה‑UI של SuperDoc — שבה
   יושבים ה‑`Ctrl+F` וה‑`Ctrl+Shift+8` שלו — איננו מרכיבים כלל, כי אנחנו
   מריצים `ui: false` (`src/engine/create-editor.ts`).

2. **תלות בפריסת המקלדת.** ההתאמה היא `event.key === 's'`. כשפריסת המקלדת
   עברית הדפדפן מדווח ב‑`key` את תו הפריסה: `Ctrl+S` נותן `ד`, `Ctrl+F` נותן
   `כ`. כלומר בעורך שכל ייעודו כתיבת עברית, ששת הקיצורים הקיימים מתים ברגע
   שהמשתמש עובר לעברית. `event.code` הוא פיזי ובלתי תלוי פריסה, והוא הפתרון.

הליקוי השני הוא באג בקוד קיים, ולכן הוא שלב 0 — גם אם לא יתווסף אף קיצור חדש.

## 2. החלטות

- **`code` ולא `key`** לכל קיצור שהוא אות. `key` משמש רק לסימני פיסוק
  (`]`, `[`, `=`), שבהם ה‑`code` עצמו משתנה בין פריסות פיזיות.
- **מודיפיירים מדויקים.** `Ctrl+S` אינו מתאים לאירוע `Ctrl+Alt+S`. כל רשומה
  מצהירה על ארבעת המודיפיירים, ו‑`Meta` שקול ל‑`Ctrl` (macOS).
- **רג'יסטרי אחד** הוא מקור האמת: ממנו נגזרים גם ה‑dispatcher וגם התוויות
  ברצועה. תווית לא תוכל עוד לשקר, כי אין דרך לכתוב אותה ידנית.
- **הפקודות עוברות דרך `CommandAdapter`** בדיוק כמו לחיצת כפתור, כדי שכשל
  יגיע למשתמש בעברית ולא ייעלם. קיצור אינו מסלול עוקף למנוע.
- **אין קיצור לפעולה חסרה.** רשומה שמפנה למזהה שאינו ב‑`COMMAND_IDS`
  (`src/engine/capabilities.ts`) מפילה את בדיקת החוזה.
- **תאימות ל‑Word** היא ברירת המחדל בבחירת הצירופים. המשתמש מגיע מ‑Word, ולא
  ממציאים לו שפה חדשה.

## 3. הארכיטקטורה

מודול חדש `src/ui/shortcuts/registry.ts` — הצהרה בלבד, בלי תלות ב‑Vue:

```ts
export interface Shortcut {
  /** מזהה יציב לרשומה, לבדיקות ולדיאלוג העזרה. */
  id: string;
  /** המקש הפיזי. אות = code; פיסוק = key. */
  code?: string;
  key?: string;
  ctrl?: boolean;   // Ctrl או Meta
  shift?: boolean;
  alt?: boolean;
  /** התווית שמוצגת ב-tooltip וברשימת הקיצורים. */
  label: string;
  /** מה זה מריץ: פקודת מנוע, או פעולת מעטפת בשם. */
  command?: CommandId;
  action?: ShellAction;
  payload?: unknown;
  /** האם הצירוף פועל גם כשהפוקוס בשדה טקסט של הממשק. */
  inTextEntry?: boolean;
  /** האם החזקת המקש חוזרת על הפעולה. */
  repeatable?: boolean;
}
```

לצדו שני מודולים:

- `src/ui/shortcuts/match.ts` — `matchShortcut(event, shortcut): boolean`, פונקציה
  טהורה. כל בדיקות הפריסה יושבות עליה.
- `src/ui/shortcuts/dispatch.ts` — `createShortcutDispatcher({ adapter, actions, isBlocked })`,
  מחזיר `handle(event)` ו‑`dispose()`. `App.vue` מפסיק להחזיק לוגיקה של
  קיצורים ורק מרכיב את זה.

`RibbonButton` מקבל `shortcut-id` במקום `shortcut`, ושולף את התווית מהרג'יסטרי.

## 4. השלבים

### שלב 0 — תשתית, ותיקון פריסת המקלדת

**מטרה:** ששת הקיצורים הקיימים עוברים לרג'יסטרי ומפסיקים למות בפריסה עברית.
אין קיצור חדש בשלב הזה — רק תשתית והחלפת מנוע ההתאמה.

**קבצים:** `src/ui/shortcuts/{registry,match,dispatch,actions}.ts` (חדשים),
`src/App.vue`, `src/ui/ribbon/common/RibbonButton.vue`, `FileTab.vue`,
`HomeTab.vue`, `src/sessions/open-flow.ts` (`saveShortcut` נבלע ונמחק).

**מה עושים:**
1. רג'יסטרי עם שש הרשומות הקיימות, ועוד שלוש שהדפדפן מטפל בהן (`Ctrl+C/X/V`)
   ומסומנות `native` — הן מתועדות ומוצגות, ואיננו נוגעים בהן.
2. `matchShortcut` על `code`.
3. dispatcher עם מדיניות פוקוס, ו-`actions.ts` שמחזיק את ההכרעות של המעטפת
   (ובהן „בזמן שמירה אין שמירה שנייה”, שהייתה `saveShortcut`).
4. `RibbonButton` מקבל `shortcut-id` מטופס ושולף תווית מהרג'יסטרי.
5. תשע התוויות שאין להן binding (`Ctrl+B/I/U`, `Ctrl+R/E/L/J`, `Ctrl+]`,
   `Ctrl+[`) **מוסרות** מהרצועה. הן חוזרות בשלבים 1–2 יחד עם ה-binding שלהן.

**תיקון לתוכנית, מתוך המימוש:** `isTextEntryTarget` **אינו** מורחב לאזור
העריכה של המנוע. הכלל הנכון הפוך — שדות הטקסט של הממשק שלנו (`input`,
`textarea`, `select`, `role="textbox"`) חוסמים קיצור מסמך, ואזור המסמך של
המנוע דווקא לא: שם הקיצורים חייבים לעבוד. בדיקה 15 מבטאת בדיוק את זה. נוסף על
כך, בדיקת הגבולות (`engine-boundaries`) אוסרת בכלל להזכיר את מאפיין העריכה
בקוד, ולכן ההבחנה היא על `tagName` ועל `role`.

**טסטים** — `tests/unit/shortcut-match.test.ts`:

### שלב 1 — הליבה שמשתמש Word מצפה לה

**מטרה:** הקיצורים שהיעדרם מורגש מיד. כולל שחרור התוויות שמשקרות היום.

| קיצור | פעולה | מקור |
|---|---|---|
| `Ctrl+Z` | בטל | `undo` |
| `Ctrl+Y`, `Ctrl+Shift+Z` | בצע שוב | `redo` |
| `Ctrl+B` / `Ctrl+I` / `Ctrl+U` | מודגש / נטוי / קו תחתון | `bold`, `italic`, `underline` |
| `Ctrl+A` | בחר הכול | Document API |
| `Ctrl+K` | קישור | `link` |
| `Ctrl+Enter` | מעבר עמוד | `src/engine/page-break.ts` |
| `Ctrl+N` / `Ctrl+O` | מסמך חדש / פתח קובץ | מעטפת |
| `F12` | שמור בשם | מעטפת |
| `Ctrl+Shift+8` | סימני עיצוב | `formatting-marks` |
| `Ctrl+Alt+1/2/3` | כותרת 1/2/3 | `linked-style` עם `stylePayload('Heading1')` |

**טסטים** — `tests/component/shortcuts-core.test.ts`, דרך ה‑harness הקיים:

1. עשר בדיקות (1‑10), אחת לכל שורה בטבלה: האירוע נורה, והמנוע קיבל את מזהה
   הפקודה הנכון עם ה‑payload הנכון.
11. `Ctrl+Y` ו‑`Ctrl+Shift+Z` מגיעים שניהם ל‑`redo`.
12. `Ctrl+B` בפריסה עברית (`key: 'נ'`) מדגיש.
13. `Ctrl+Z` כשאין היסטוריה — נחסם, וההודעה „אין פעולה לבטל” מוצגת.
14. `Ctrl+K` בלי בחירה — נחסם עם ההודעה של המנוע ולא נופל.
15. `Ctrl+Enter` בתוך שדה טקסט של הממשק אינו מוסיף מעבר עמוד.
16. `Ctrl+N` / `Ctrl+O` על מסמך מלוכלך — עוברים דרך `decideDocumentSwitch`
    ואינם מוחקים עבודה בלי לשאול.
17. `Ctrl+A` מגיע ל‑Document API ולא לפקודה.
18. `Ctrl+Alt+1` מעביר `{ style: 'Heading 1' }` שעובר ולידציה של המנוע.
19. `Ctrl+Shift+8` מדליק ומכבה — הצירוף הוא toggle, לא set.
20. כל עשרת הצירופים קוראים `preventDefault`.

**ממצא מבני, מתוך המימוש:** לשוניות הרצועה מורכבות רק כשהן פעילות
(„mount on active”), ולכן **כל פעולה שיושבת בתוך רכיב לשונית אינה נגישה
לקיצור גלובלי**. זה נכון ל‑`Ctrl+K` (הדיאלוג של הקישור חי ב‑`InsertTab`),
ויהיה נכון גם ל‑`Ctrl+Alt+F/D` (`ReferencesTab`), `Ctrl+Alt+M` (`ReviewTab`)
ו‑`Ctrl+Shift+Q` (`OtzariaTab`).

מה שכן עבר בשלב הזה: הפקודות (`undo`, `redo`, `bold`…) רצות דרך האדפטר של
המעטפת, ו„בחר הכל” ו„מעבר עמוד” דרך מודולי המנוע (`selectWholeDocument`,
`startParagraphOnNewPage`) — כולם אינם תלויים בלשונית. `Ctrl+K` הוא היחיד
שנשאר, והוא עובר לשלב 1א.

**הבחנה שנקבעה כאן:** כפתור מנוטרל אינו נלחץ; קיצור אין דרך „לנטרל”. לכן
קיצור לפקודה שאינה זמינה **כן** מגיע לאדפטר, והמנוע מסרב עם הודעה בעברית —
עדיף על שקט. זו הבדיקה „פקודה שאינה זמינה: המנוע מסרב, והמשתמש מקבל הסבר”.

**בוצע כאשר:** תשע התוויות שהוסרו בשלב 0 חזרו — הפעם עם binding אמיתי.

**קומיט:** `קיצורי מקלדת: ליבת העריכה — ביטול, עיצוב תו, מעבר עמוד ובחר הכל`

### שלב 1א — הדיאלוגים עוברים מהלשוניות למעטפת

**מטרה:** `Ctrl+K`, ופתיחת החסימה לשלבים 4–5.

הדיאלוגים של הממשק שייכים למעטפת, לא ללשונית: `FindReplaceDialog`
ו‑`AboutDialog` כבר יושבים ב‑`App.vue`, ו‑`LinkDialog` הוא היוצא מן הכלל.
הוא עובר לשם, וכפתור „קישור” ב‑`InsertTab` פולט `open-link` כלפי מעלה — בדיוק
כמו `@open-find` ו‑`@about` שכבר עוברים כך.

| קיצור | פעולה |
|---|---|
| `Ctrl+K` | פתיחת דיאלוג הקישור על הבחירה הנוכחית |

**טסטים:**

1. `Ctrl+K` פותח את הדיאלוג מכל לשונית — כולל כשלשונית „בית” היא הפעילה.
2. הדיאלוג נפתח עם תצלום הבחירה, ולא עם בחירה שכבר אבדה למיקוד.
3. אישור עם טווח מסומן שולח `hyperlinks.wrap` בלי `text`.
4. אישור בלי טווח שולח `text`.
5. כתובת פסולה נחסמת בדיאלוג ואינה מגיעה לפקודה.
6. `Ctrl+K` בלי מסמך פתוח אינו פותח דיאלוג ריק.
7. `Escape` סוגר את דיאלוג הקישור ומחזיר פוקוס.
8. כפתור „קישור” בלשונית „הוספה” מגיע לאותו דיאלוג בדיוק — מסלול אחד.
9. `Ctrl+K` בשדה טקסט של הממשק אינו נתפס.
10. הבדיקות הקיימות של זרימת הקישור עוברות עם הרכיב במקומו החדש.

**קומיט:** `קיצורי מקלדת: דיאלוג הקישור עובר למעטפת, ו-Ctrl+K נפתח מכל לשונית`

### QA #1 — אחרי שלב 1 ✔ בוצע

הסוכן הריץ `typecheck` ואת חבילת הבדיקות (עברו), וסקר את שלושת הקומיטים.
**שישה ליקויים אמיתיים, כולם נסגרו לפני שלב 2:**

1. **`Ctrl+N` נכנס בלי כיסוי**, ובדיקה 16 (מסמך מלוכלך עובר ב‑`decideDocumentSwitch`)
   לא מומשה כלל — כלומר הקיצור המסוכן ביותר בשלב היה הכי פחות בדוק. נוספו
   שלוש בדיקות מעטפת, ובהן „`Ctrl+N` על מסמך מלוכלך שואל לפני שהוא מוחק
   עבודה”. תוך כדי התברר ש‑`Ctrl+O` פותח את בורר הקבצים **לפני** השאלה, בדיוק
   כמו הכפתור — וזה תועד בבדיקה במקום להשתנות.
2. **המנתב התעלם מ‑`event.defaultPrevented`.** המאזין יושב על `window` בשלב
   ה‑bubble, אחרי ה‑keymap של המנוע; אם המנוע קושר `Ctrl+B` בעצמו, התוצאה
   הייתה הדגשה ומיד ביטולה — „הקיצור לא עובד” בלי שום שגיאה. §6.3 דרש את
   ההגנה הזאת, והיא לא הייתה בקוד. נוספה.
3. **`Escape` נבלע תמיד**, גם כשלא היה מה לסגור — נסיגה מול `main`, ובליעה
   שעלולה לשבור את ה‑`Escape` של המנוע. `runAction` מחזיר עכשיו „טופל”,
   והמנתב בולע רק לפיו.
4. **ארבע תוויות קשיחות ב‑`TitleBar.vue`** (`בטל Ctrl+Z` וחבריו) — מחוץ
   ל‑`RibbonButton`, ולכן בדיקת ה‑`shortcut=` לא ראתה אותן. הן נשלפות
   מהרשימה, ובדיקת חוזה חדשה סורקת כל `title`/`tooltip`/`aria-label` שמכיל
   צירוף. הרשת אומתה: היא נכשלת על הפרה מושתלת.
5. **הרשת נגד נסיגת הפריסה הייתה צרה** — תפסה רק `.key === 'x'`. הורחבה
   למרכאות כפולות, `toUpperCase` והשוואה הפוכה.
6. **`Ctrl+Enter` לא נתפס ב‑Enter של הלוח הנומרי.** `code` מקבל עכשיו רשימה,
   והרשומה מכסה `Enter` ו‑`NumpadEnter`.

נסגרו גם: `payload` של הכותרות עובר דרך `stylePayload` הקנוני ולא נבנה ביד;
סריקת התוויות רצה על ארבע לשוניות ולא על אחת; והערה מיושנת ב‑`HomeTab` שטענה
ש„אין במנוע select-all ולכן אין קיצור” — בעוד שהקיצור קיים ומנתב לאותו מסלול
בדיוק שהכפתור מנתב אליו.

**ממצאים שנדחו, עם נימוק:**

- „`Heading1` צריך להיות `Heading 1`” — המימוש צודק והמסמך טעה.
  `engine/style-gallery.ts` מנרמל בלי רווח, וכך המנוע מקבל. הטבלה תוקנה.
- „`Ctrl+Alt` הוא AltGr ב‑Windows” — נכון, אך זה הצירוף של Word עצמו. עבר
  לטבלת שער Windows (§6) לאימות חי.

  הקיצורים בשלב 6 בא לפתור. פקד אחד אינו יכול להציג שני צירופים.

### QA #2 — אחרי שלב 3 ✔ בוצע

הסוכן לא הסתפק בקריאת קוד: הוא **מדד** את שלוש הפריסות הרלוונטיות
(`00000409` US, `0000040D` עברית ישנה, `0002040D` עברית סטנדרטית) מול
`ToUnicodeEx`, ובנה את טבלת 44 הצירופים מהרג'יסטרי. שני ממצאים מהמדידה
הפכו החלטה שנכתבה כאן בשלב 0 — ובצדק.

**חוסם:**

1. **`Ctrl+Shift+=` (כתב עילי) לא היה יורה לעולם.** הרשומה נשענה על
   `key: '='`, אבל עם `Shift` הדפדפן מדווח `+` בכל שלוש הפריסות. ההתאמה לא
   הייתה מתקיימת אפילו בלטינית — והרצועה בינתיים הציגה tooltip „(Ctrl+Shift+=)”
   על כפתור הכתב העילי. כלומר בדיוק הליקוי שהתוכנית באה לחסל, בכניסה חדשה.
   מה שהסתיר אותו: הבדיקות בנו `{ key: '=', shiftKey: true }` — אירוע
   שדפדפן אינו יכול לייצר.

**ראוי לתיקון, ותוקן:**

2. **בפריסה עברית הסוגריים ממושקפים.** המקש הפיזי `BracketLeft` מפיק „]”
   ו‑`BracketRight` מפיק „[”. מכיוון שההתאמה הייתה לפי תו, בפריסה עברית
   „הגדל” ו„הקטן” התחלפו — בדיוק בפריסה שהתוסף נועד לה.
3. **`Ctrl+Alt+3` חוטף תו ב‑AltGr** בפריסה העברית הסטנדרטית (U+00AC).
   `Ctrl+Alt+1` ו‑`Ctrl+Alt+2` נקיים בשתי הפריסות העבריות.
4. **דיאלוג הקישור הוא `aria-modal` ולא נספר כמודאל.** מעליו רצו קיצורי
   מסמך על המסמך שמתחת — נסיגה מול בדיקה 17 של שלב 0.
5. **הכיווניות דרשה ש‑`Ctrl` יילחץ לפני `Shift`.** סדר הלחיצה אינו משהו
   שמשתמש חושב עליו.
6. **`Ctrl+K` בלי מסמך פתוח** פתח דיאלוג ריק.

**ההחלטה שהתהפכה:** §2 קבע ש„סימני פיסוק לפי `key`, כי שם ה‑`code` נודד”.
המדידה הראתה את ההפך, ולכן **כל הרשומות עברו ל‑`code`**. השדה `key` נשאר
כפתח מילוט מתועד, ובדיקת חוזה חדשה עוצרת כל רשומה שתשען עליו — מי שיעשה זאת
יצטרך למדוד קודם, כמו שנעשה כאן.

נסגרו גם: `Alt` פוסל חימוש כיווניות (AltGr), איפוס על `blur` (ה‑`keyup`
מגיע לחלון אחר), ותיעוד ההתנהגות של שני `Shift` בו‑זמנית.

**ממצאים שנדחו, עם נימוק:**

- **`Ctrl+Shift+>` / `Ctrl+Shift+<` לא ימומשו.** ב‑Word `Ctrl+]` מקדם
  בנקודה ו‑`Ctrl+Shift+>` בסולם. אצלנו `Ctrl+]` **כבר** מקדם בסולם הגדלים של
  Word (`grownFontSize`), ולכן הצירוף השני היה כפילות מדויקת. הנספח תוקן.
- **`Ctrl+Shift+V` („הדבק עיצוב”) לא ימומש.** המנוע חושף `copy-format` כמתג
  יחיד, ואין פקודה נפרדת ל„החל את העיצוב שהועתק”. `Ctrl+Shift+V` היה מכבה
  את המתג — כלומר עושה את ההפך ממה שהתווית מבטיחה. הנספח תוקן.
- **התווית „Ctrl + Shift ימני” מערבבת כתבים ונקראת הפוך ב‑RTL.** נכון,
  וזה בדיוק מה שבדיקה 9 בשלב 6 באה לפתור (`dir="ltr"` סביב הצירוף בדיאלוג
  הקיצורים). לא משנים תווית פעמיים.
- **`Ctrl+Shift+X` אינו הצירוף של Word ל„קו חוצה”.** נכון — הוא מוסכמה של
  Google Docs. הוא נשאר: אין ל‑Word ברירת מחדל ל„קו חוצה”, והצירוף פנוי.

## 5. סוכן ה‑QA

בכל נקודת QA מופעל סוכן נפרד, שאינו כותב קוד אלא בודק. הוא מקבל את המסמך הזה,
את ה‑diff מאז נקודת ה‑QA הקודמת, ומריץ `npm run verify`. המנדט שלו:

1. **נאמנות לתוכנית** — האם כל שורה בטבלת השלב מומשה, ואם לא, מה חסר.
2. **תוויות מול bindings** — תווית שאין לה binding, או binding שאין לו תווית.
3. **תלות בפריסה** — כל `event.key` שמושווה לאות היא נסיגה לבאג של שלב 0.
4. **התנגשויות** — בין רשומות, מול קיצורי הדפדפן, ומול Word.
5. **פקודות מתות** — `command` שאינו ב‑`COMMAND_IDS`.
6. **כיסוי** — כל צירוף חדש חייב לפחות בדיקה אחת שמאמתת את מזהה הפקודה
   ואת ה‑payload, ולא רק ש„משהו נקרא”.
7. **מסלול הכשל** — כל צירוף שאפשר להפעיל במצב חסום מחזיר הודעה בעברית.
8. **גבול המנוע** — הקיצורים אינם נוגעים ב‑SuperDoc ישירות, אלא דרך האדפטר.

ממצא שהסוכן מעלה נסגר לפני שנפתח השלב הבא. אם ממצא נדחה — הדחייה נרשמת כאן
בנימוק, ולא נשארת בעל פה.

## 6. שער Windows

בדיקות ה‑vitest אינן מרימות את מנוע ה‑DOCX, ולכן שלושה דברים נבדקים ידנית
בבנייה ארוזה, לפי `docs/spike-windows.md`:

1. אילו צירופים ה‑WebView2 של אוצריא בולע לפנינו — חשודים: `Ctrl+N`,
   `Ctrl+O`, `Ctrl+P`, `Ctrl+W`, `F11`, `F12`.
1א. `Ctrl+Shift+N` ו‑`Ctrl+Shift+C` הם „חלון פרטי חדש” ו„בדוק אלמנט” של
   Chromium — מקשי האצה שדף אינו יכול לבטל. יש לוודא מה קורה בתוך WebView2.
1ב. `Ctrl+Alt+3` **נמדד** כמתנגש בשכבת AltGr של הפריסה העברית הסטנדרטית
   (`0002040D`): הצירוף מפיק שם U+00AC, ואנחנו בולעים אותו. `Ctrl+Alt+1`
   ו‑`Ctrl+Alt+2` נקיים. הצירוף נשאר מפני שהוא של Word, ומפני שהתו הזה אינו
   נכתב בכתיבה תורנית — אם יתברר אחרת בשימוש, יש להסיר את `heading-3` בלבד.
2. האם צירופי `Ctrl` + `Shift` ימני/שמאלי מגיעים אלינו בכלל.
3. האם מנוע העריכה קושר בעצמו `Ctrl+B/I/U` — ואז הרשומות שלנו חייבות לוודא
   שאין הפעלה כפולה.

כל ממצא כאן נרשם בטבלה במסמך הזה, עם החלופה שנבחרה.
