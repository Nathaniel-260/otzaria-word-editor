# זיהוי רשימות בהקלדה — מה Word עושה, כפי שנמדד

- תאריך: 15.9.2026
- נמדד על: Microsoft Office 16 (`C:\Program Files\Microsoft Office\root\Office16`), ממשק עברי
- נבדק מול: המימוש הפתוח המקביל ב‑LibreOffice Writer (`sw/source/core/edit/autofmt.cxx`)

המסמך הזה הוא **מדידה**, לא תיעוד. כל שורה בטבלאות כאן הוקלדה ל‑Word חי ונקראה
בחזרה דרך ה‑COM שלו. הוא קיים כדי שההחלטות ב‑`docs/list-autoformat-plan.md`
יישענו על מה ש‑Word באמת עושה, ולא על מה שכתוב עליו.

---

## 1. איך נמדד

שני מסלולים נפסלו לפני שנמצא אחד שעובד:

1. **`Selection.TypeText` דרך COM אינו מפעיל את הזיהוי.** נמדד: ארבע צורות
   (`1. `, `1) `, `* `, `- `) הוקלדו כך, וכולן חזרו `ListType=0` — טקסט רגיל.
   הדגלים היו דלוקים (`AutoFormatAsYouTypeApplyNumberedLists=True`,
   `…ApplyBulletedLists=True`). כלומר AutoFormat‑תוך‑כדי‑הקלדה תלוי במסלול
   הקלט של המקלדת, ולא בכתיבה למודל.

2. **`SendInput` (הקשות אמיתיות) עובד, ומסוכן.** הוא שולח לחלון **החזית**,
   והפוקוס חוזר לחלון שממנו הופעל הסקריפט מיד אחרי הקריאה הראשונה ל‑COM.
   בריצה כזאת חמש שורות בדיקה הוקלדו לחלון של המפעיל. שער חד‑פעמי לפני
   הריצה אינו מספיק — הוא נדרש לפני **כל** משלוח, או שלא בכלל.

3. **מה שנבחר: `PostMessage(WM_CHAR)` אל חלון העריכה `_WwG` של Word.** הוא
   אינו נוגע בפוקוס כלל, ולכן אינו יכול לדלוף. מקרה‑בקרה (`1. ` חייב להפוך
   לרשימה) רץ ראשון בכל ריצה; אם הוא נכשל, השיטה אינה מודדת דבר והריצה
   נפסלת. הסקריפטים: `scratchpad/word-probe-3.ps1`, `word-probe-4.ps1`.

## 2. הממצא הראשון — ההמרה קורית על הרווח, והפסקה עוד ריקה

התיעוד הרווח (גם באתרי עזרה ותיקים) אומר „הקלד סימן, רווח, טקסט, ואז Enter”.
זה **אינו** מה שנמדד. אחרי `1` `.` `רווח` בלבד, לפני שהוקלד תו טקסט אחד:

```
listType=3  listValue=1  listString='1.'  style='פיסקת רשימה'  left=36  first=-18  text=''
```

הפסקה כבר רשימה, הסמן כבר אחרי הסמן המצויר, והטקסט המוקלד — `1. ` — **נבלע**
(`text=''`). זו נקודת ההחלטה היחידה: **הרווח או ה‑Tab שאחרי המפריד**. גם
`1.` ואחריו Tab נמדד כמפעיל.

## 3. אילו צורות Word מזהה, ואילו לא

כל השורות: הצורה הוקלדה לתחילת פסקה ריקה, ונקרא המצב מיד אחרי תו ההפעלה.

### ממוספרות

| הוקלד | הומר? | הסמן שצויר | הזחה (שמאל / שורה ראשונה) |
|---|---|---|---|
| `1.` + רווח | כן | `1.` | 36 / ‎-18 |
| `1)` + רווח | כן | `1)` | 36 / ‎-18 |
| `1-` + רווח | כן | `1-` | 36 / ‎-18 |
| `1>` + רווח | כן | `1>` | 36 / ‎-18 |
| `(1)` + רווח | כן | `(1)` | 36 / ‎-18 |
| `1.` + Tab | כן | `1.` | 36 / ‎-18 |
| `0.` + רווח | כן — **מתחיל מ‑0** | `0.` | 36 / ‎-18 |
| `5.` + רווח | **לא** | — | — |
| `a.` + רווח | כן | `a.` | 36 / ‎-18 |
| `a)` + רווח | כן | `a)` | 36 / ‎-18 |
| `A.` + רווח | כן | `A.` | 36 / ‎-18 |
| `i.` + רווח | כן | `i.` | 54 / ‎-36 |
| `I.` + רווח | כן | `I.` | 54 / ‎-36 |

### תבליטים

| הוקלד | הומר? | הסמן |
|---|---|---|
| `*` + רווח | כן | סימן (גופן Symbol) |
| `-` + רווח | כן | `-` (גופן Arial) |
| `>` + רווח | כן | סימן |
| `->` + רווח | כן | סימן |
| `=>` + רווח | כן | סימן |
| `+` + רווח | **לא** | — |

`+` הוא הפרש מדוד מול LibreOffice, שמקבל אותו (`pBulletChar` שם הוא
`'+', '*', '-', 0x2013, 0x2014`).

### עברית — וזו התשובה שאין עליה תיעוד

| הוקלד | הומר? | הסמן |
|---|---|---|
| `א.` + רווח | **כן** | `א.` |
| `א)` + רווח | **כן** | `א)` |
| `(א)` + רווח | **כן** | `(א)` |
| `א-` + רווח | **כן** | `א-` |
| `א'` + רווח | **לא** | — |
| `ב.` + רווח | **לא** | — |
| `שלום.` + רווח | לא | — |

Word מזהה אות עברית בדיוק כמו `a` ו‑`1`, ובאותן ארבע צורות מפריד. שתי
השלילות אינן מקריות והן החשובות כאן:

**והסוגר הממוראה — נמדד בנפרד.** במסמך RTL הסוגר שמצויר על המסך אינו התו
הלוגי: `)` אחרי אות עברית מצטייר בצורת `(`. נבדק אם Word מקבל גם את התו השני,
בשני כיווני קריאה של הפסקה (`ParagraphFormat.ReadingOrder` ‏RTL ו‑LTR):

| הוקלד | LTR | RTL |
|---|---|---|
| `א` + `)` | הומר, `%1)` | הומר, `%1)` |
| `א` + `(` | **לא** | **לא** |
| `1` + `(` | **לא** | **לא** |
| `(א)` | הומר, `(%1)` | הומר, `(%1)` |
| `)א(` | **לא** | **לא** |

כלומר רק התו הלוגי `)` (‏U+0029) מתקבל, וכיוון הקריאה של הפסקה אינו משנה דבר.
זה גם מה שהמקלדת העברית של Windows מייצרת ב‑Shift+0 — ולכן אין כאן פער, ואין
צורך לקבל את התו הממוראה.

- **`ב.` נדחה** מאותה סיבה ש‑`5.` נדחה — ראו §5.
- **`א'` (גרש) נדחה.** זו הצורה הנפוצה ביותר בכתיבה תורנית, ו‑Word בכל זאת
  אינו מקבל אותה. ההסבר המתבקש: `א'` בתחילת פסקה הוא גם „א׳ בניסן”, „ר' יוסי”
  וכל קיצור אחר — קבלה שלה הייתה הופכת פסקאות שלמות לרשימות בלי שביקשו.

## 4. מה Word כותב בפועל — וזה מה שאנחנו צריכים לכתוב

נקרא מ‑`ListFormat.ListTemplate.ListLevels(1)` אחרי כל המרה:

| הוקלד | `NumberStyle` | `NumberFormat` (‏`lvlText`) | `StartAt` | מיקום סמן / טקסט |
|---|---|---|---|---|
| `1.` | 0 — `decimal` | `%1.` | 1 | 18 / 36 |
| `1)` | 0 — `decimal` | `%1)` | 1 | 18 / 36 |
| `(1)` | 0 — `decimal` | `(%1)` | 1 | 18 / 36 |
| `1-` | 0 — `decimal` | `%1-` | 1 | 18 / 36 |
| `a.` | 4 — `lowerLetter` | `%1.` | 1 | 18 / 36 |
| `A.` | 3 — `upperLetter` | `%1.` | 1 | 18 / 36 |
| `i.` | 2 — `lowerRoman` | `%1.` | 1 | 18 / 54 |
| `א.` | **45 — `hebrew1`** | `%1.` | 1 | 18 / 36 |
| `א)` | **45 — `hebrew1`** | `%1)` | 1 | 18 / 36 |
| `(א)` | **45 — `hebrew1`** | `(%1)` | 1 | 18 / 36 |
| `א-` | **45 — `hebrew1`** | `%1-` | 1 | 18 / 36 |
| `*` | 23 — תבליט | `` (ריק) | — | גופן Symbol |
| `-` | 23 — תבליט | `-` | — | גופן Arial |

שתי מסקנות מעשיות:

1. **המפריד שהוקלד נשמר כתבנית הסמן.** מי שהקליד `א)` מקבל `%1)` ולא `%1.` —
   הרשימה כולה תמשיך בסוגר, לא בנקודה. זה אינו פרט קוסמטי אלא עיקר ההתנהגות.
2. **`א` ממופה ל‑`hebrew1` — גימטריה** (‏א ב ג … י יא יב), ולא לסדר האלף‑בית.
   זה בדיוק ה‑`numFmt` ש‑`src/engine/lists.ts` כבר מודד כעובד אצלנו.

## 5. ערך ההתחלה — למה `5.` נדחה ו‑`3.` התקבל

`5. ` במסמך ריק אינו הופך לרשימה. אבל אחרי רשימה שהגיעה ל‑2 ויצאו ממנה,
`3. ` **כן** הפך לרשימה, ו‑`listValue=3`:

```
after exit: listType=0
typed '3. ' -> listType=3 listString='3.' listValue=3
```

כלומר הכלל אינו „רק 1”, אלא: **1 או 0 פותחים רשימה חדשה; כל ערך אחר מתקבל רק
אם הוא ממשיך סביר של הרשימה הקודמת במסמך.** אותו כלל בדיוק הוא שדוחה את `ב.`
במסמך שאין בו רשימה עברית קודמת.

## 6. מה קורה אחר כך

**המשך ב‑Enter.** נמדד על `א) `:

```
p1: listString='א)'  →  Enter  →  p2: listString='ב)'  →  Enter  →  p3: listString='ג)'
```

**Enter על פריט ריק מסיים את הרשימה.** מ‑`ג)` הריק, Enter נוסף החזיר את הפסקה
ל‑`רגיל` עם הזחה 0 — והפריט הריק **נבלע** (מניין הפסקאות נשאר 3, לא 4).

**Backspace מיד אחרי ההמרה מסיר את המספור בלבד.** נמדד:

```
before BS: listType=3
after  BS: listType=0  style='פיסקת רשימה'  left=36  text=''
```

הסגנון וההזחה **נשארים**. כלומר Backspace אינו „ביטול ההמרה” — זו פעולה חלקית.
הביטול המלא ב‑Word הוא Ctrl+Z, או „בטל מספור אוטומטי” בכפתור ה‑AutoCorrect
(סמל הברק) שמופיע ליד ההמרה.

## 7. מה LibreOffice עושה אחרת

`SwAutoFormat::GetDigitLevel` (‏`sw/source/core/edit/autofmt.cxx`) הוא המימוש
הפתוח של אותה תכונה, והוא רחב יותר:

- מפרידים: `.` `(` `)` וגם המקבילות המלאות‑רוחב (`0x3002`, `0xff0e`, `0xFF08`,
  `0xFF09`).
- ספרות: `'0'`‑`'9'` וגם ספרות מלאות‑רוחב (`0xff10`‑`0xff19`).
- תווי תבליט: `'+' '*' '-' 0x2013 0x2014` — כולל `+` ש‑Word דוחה.
- **קינון אמיתי**: `1.1.1` מפורק לרמות (עד `MAXLEVEL`), עם עד 3 ספרות לרמה.
- אימות רומיות בפני עצמו (m d c l x v i), עם בדיקת סדר.

הקינון הוא ההפרש המשמעותי: Word מזהה רמה אחת בלבד בהקלדה.

## 8. מה מכל זה נכנס אלינו

הכרעות מלאות — ב‑`docs/list-autoformat-plan.md`. בקצרה:

- **נכנס:** ההמרה על הרווח/Tab; ארבע צורות המפריד `.` `)` `-` וגם `(…)`;
  שמירת המפריד ב‑`lvlText`; `א → hebrew1`; `0`/`1`/`a`/`A`/`i`/`I`/`א` בלבד
  כפותחי רשימה; תבליטים `*` `-` `>` `->` `=>`.
- **נכנס בשינוי:** `+` מתקבל גם הוא (אין סיבה לשחזר דווקא את השלילה הזאת,
  ו‑LibreOffice מקבל).
- **לא נכנס בשלב הזה:** `א'` בגרש — מסוכן בדיוק כפי ש‑Word חשש; קינון `1.1.1`;
  והמשך לפי הרשימה הקודמת (§5) — פותחים 0/1/א בלבד.
